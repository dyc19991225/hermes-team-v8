# V8.1 升级说明

2026-11-17，本地 Hermes Team 编排方案升级到 8.1.0，并完成正式安装。随后公开脱敏运行源码、测试、配置模板和验证摘要，见 [运行说明](runtime-setup.md)；V8.1 不是上游 Hermes 的版本号。

## 已复现问题与修复

| 问题 | 修复方式 | 验证 |
| --- | --- | --- |
| 另一个项目的慢目录审计占用 SQLite 写事务，当前任务心跳报 database is locked | 在事务外准备执行器，短事务提交前重新核对身份和权限 | 慢准备与正在运行的心跳回归通过 |
| 结果含孤立 Unicode surrogate 时，JSON 写出失败导致任务 RUNNING 和锁残留 | 安全 JSON 编码；持久化异常仍进行终态和 token 范围收尾 | 异常 Unicode 与结果写入失败回归通过 |
| Codex Worker 继承 Windows GBK 标准流，emoji 输出失败 | 显式 UTF-8 与可转义输出，握手等待保留异步事件 | 中文和 emoji 回归、真实只读调用通过 |
| AGY 将完整提示放入 argv，长提示触发 Windows error 206 | 单条 stream-json user 消息经 stdin 传递，最终参数长度预检 | 十万字符传输构造、消息注入回归及真实只读调用通过 |

AGY 真实调用发现 text print 模式未读取标准输入，初始两次参数诊断失败；最终改用 stream-json 后成功。离线 mock 不能替代真实协议验证。

## 新增工作流

- **明确排队**：`run` 在空闲时启动，忙时等待；`enqueue` 明确加入等待队列。仅明确排队的工作能自动接续，不重跑历史 CREATED / DRY_RUN 任务。
- **同项目阶段依赖**：创建时引用最多 16 个已有任务。前置执行成功且验收通过后继续；失败、取消或拒绝会阻塞依赖阶段。
- **独立验收记录**：`review` 记录接受 / 拒绝及证据。决定不可改写，返工创建新任务。证据格式检查不能证明自报测试真实执行，也不替代质量判断。
- **预算与用量**：日志默认 16 MiB；可选已上报 Token 阈值；缓存 Token 单列。执行器可能完成时才上报，不能保证账单上限。默认不自动重试。
- **版本诊断**：`doctor` 查看 CLI 版本及变化，`doctor --probe` 只做 Codex 原生权限握手，不发起模型 turn。

执行继续全局串行，包括只读任务。本地观察进程负责队列接续，单次最多一小时；可用 `run-next` 恢复。后台等待只释放匹配 token 的预留，过期 Worker 不能将已取消任务重新排队。

新命令需绑定真实运行会话。Hermes Hook 自动注入并验证 session_id；普通终端需显式传入，不能据普通终端测试声称完成 Hook 隔离验收。浏览器验证默认交给 Codex，AGY 继续禁止终端、MCP 和浏览器。

## 安装和验收

隔离目录和正式安装目录分别运行完整回归，**各 101 项通过**。正式目录用时 43.835 秒。真实 Codex 和 AGY 只读任务成功读取临时项目文件，原文件内容保留；Codex 权限握手没有发起模型 turn。正式 Hook 的会话注入、范围拒绝和 doctor 入口验证通过，Hermes Hook 及配置健康检查通过。

本次 CLI 版本为 Codex 0.169.0、Claude Code 2.1.322、AGY 1.5.5。Claude 验证限于版本、适配器和回归，没有重新发起真实 Claude 模型任务。

激活前通过 SQLite 在线备份保存账本。迁移前后逐表内容摘要一致：135 个任务、14,773 条事件、4 个会话绑定，锁数量均为 0。原 Hook 和执行器配置摘要未变化，临时验证绑定已清理，维护状态已解除。

本次没有重启用户正在运行的 Hermes。建议新开对话以加载新版管理 Skill。

完整本地测试输出的公开副本见 [V8.1 回归记录](../evidence/v8.1-local-regression-2026-11-17.txt)，结构化摘要见 [V8.1 测试摘要](../evidence/v8.1-test-summary.json)。包含机器目录、会话内容的原始在线日志和备份保留在本地。

## 仍需后续验证

本次验证没有覆盖长期队列运行、全套 CLI 在线文件边界复测、跨平台安装和第三方独立复现，也没有量化费用或完成率变化。历史 JSON-RPC lone leading surrogate 失败的完整根因仍未确认；新增编码和结果持久化回归不意味着两者具有相同根因。

回退时先停止派发、完成或取消新队列，并确认相关进程和锁结束，再恢复原代码与文档。迁移只增加表；已经产生新任务后，不得用旧数据库快照覆盖当前账本。
